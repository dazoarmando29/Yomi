`Platforms`/`Runtimes` layout) fails while building the SDK's clang modules
(`SwiftShims`/`CDispatch` module maps can't resolve MSVC headers in SwiftPM's
module-validation path), before any project code is reached. A plain `swiftc`
compile of a trivial file succeeds with the same environment, so this is a
toolchain/SwiftPM interaction issue on Windows, not a code issue. Full output is
reproducible with the commands in `IOS_BUILD_GUIDE.md` §6.

## 5. CI

`.github/workflows/ios-ci.yml` runs on pushes/PRs touching `ios/`:

1. `project-lint` (ubuntu): `python3 ios/tools/generate_xcodeproj.py --check`
2. `yomikit-tests` (macos): `swift test --package-path ios/YomiKit` + log artifact
3. `build-ios-app` (macos): unsigned simulator build via `xcodebuild`, log + `.app` artifact
4. `build-signed-ipa` (manual dispatch, optional): signed archive → IPA artifact when
   repository signing secrets are configured

CI logs are the authoritative record for macOS-side results; this file is updated
with their output after each run.
