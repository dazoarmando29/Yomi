# Yomi iOS Port — Architecture & Plan

Status: implementation in progress on branch `feature/ios-port`.
Primary test target: iPhone 18 Pro Max (physical device).
Dev host audited: Windows 11 Pro (no Xcode; see `IOS_BUILD_GUIDE.md` for the macOS build workflow).

---

## 1. Codebase audit summary (Android)

Yomi is a fork of **Mihon v0.21.3** (itself a Tachiyomi successor): Kotlin 2.4, Jetpack Compose,
Voyager navigation, SQLDelight persistence, Coil 3 image loading, OkHttp 5 + RxJava networking,
kotlinx.serialization (Protobuf) backups, moko-resources strings, WorkManager background jobs,
Glance widgets, Firebase telemetry, Shizuku/PackageInstaller extension installation.

Key modules (see `settings.gradle.kts`):

| Module | Purpose | iOS verdict |
|---|---|---|
| `app` | Compose UI, reader, downloads, backups, extensions | Ported to SwiftUI (rewrite) |
| `domain` | Models + interactors (Manga, Chapter, Category, History, Track, Backup models) | Semantics ported 1:1 to `YomiKit`; code itself is Android/coroutines-coupled |
| `data` | SQLDelight schema + repositories | Schema mirrored in `YomiKit` JSON store; SQLDelight driver is Android/JVM |
| `source-api` | `Source`/`HttpSource`/`CatalogueSource` contracts | API shape ported to `YomiKit.SourceProvider` |
| `source-local` | Local CBZ/directory source | Supported later (post-v1) |
| `core:*` | archive, common, metro (DI) | Only small utilities ported |
| `presentation-core`, `presentation-widget` | Compose theme/widgets | Theme tokens ported; Glance widgets unsupported on iOS |
| `i18n`, `icons`, `telemetry` | Resources, icons, Firebase | Branding reused; Firebase optional/not ported |

## 2. Architecture decision: native SwiftUI + `YomiKit` portability layer

**Chosen: native SwiftUI app over Kotlin Multiplatform.**

Justification (based on the actual code, not generic preference):

1. **Real shareable surface is small.** The domain layer compiles against coroutines,
   kotlinx-datetime, injekt DI and Android-adjacent types; `data` requires SQLDelight Android
   drivers; `app` is Compose + AndroidX everywhere. KMP would share only model *shapes* and a
   handful of use cases — after adding Kotlin/Native, cinterop and Xcode toolchain friction to a
   Windows-based workflow.
2. **The hard parts are platform-bound anyway.** The reader (Surface/Canvas, subsampling image
   views), the download manager (WorkManager, foreground services), and especially the extension
   system (APK installation, `DelegateLastClassLoader` dynamic code loading — see Phase 3 section
   in `IOS_COMPATIBILITY.md`) must be rewritten natively regardless.
3. **Performance and maintenance.** SwiftUI + Foundation/URLConcurrency gives native scrolling,
   native image caching behavior, and lets the iOS app evolve without dragging the Android build.
4. **Verification on the dev host.** A pure-Swift `YomiKit` Swift package can be unit-tested
   headlessly (`swift test`) on macOS runners and locally wherever a Swift toolchain exists, while
   the app target is validated by `xcodebuild` in CI.

**Portability layer = specification parity, not code sharing.** `YomiKit` deliberately mirrors
the Android semantics that cross app boundaries:

- Backup format: gzipped Protobuf with **identical field numbers** (`Backup.kt`, `BackupManga.kt`,
  `BackupChapter.kt`, `BackupCategory.kt`, `BackupHistory.kt`, `BackupSource.kt` in
  `app/src/main/java/eu/kanade/tachiyomi/data/backup/models/`) — parsed by a hand-written
  wire-format decoder (no remote code, no schema DSL).
- Source IDs: the MD5-derived 64-bit ID from `HttpSource.generateId` (sign bit cleared), so backup
  source mapping works across platforms.
- Reading-mode flag values (`ReadingMode.kt`: 0 default, 1 L2R, 2 R2L, 3 vertical, 4 webtoon,
  5 continuous vertical), chapter flag bits (`Flag.kt`), chapter ordering (`ChapterSort.kt`,
  `ChapterRecognition.kt`).
- Library semantics: categories, favorites (`user_favorite_at`), read/bookmark/last-page-read,
  history with read duration — mirroring `data/src/main/sqldelight/tachiyomi/data/*.sq`.

## 4. Feature architecture

- **Library** — `LibraryStore` (actor) with atomic JSON persistence (`library.json`), indexes for
  fast search; SwiftUI `LazyVGrid`, category chips, sort/filter sheets, unread badges,
  continue-reading row built from history + chapter progress.
- **Discovery** — `SourceProvider` protocol (async, mirrors `HttpSource` semantics:
  popular/search/details/chapters/pages). Registry ships `SampleSource` (deterministic,
  authorized sample content) and is the extension point for future native connectors.
- **Reader** — paged L2R/R2L and vertical/webtoon modes, pinch-zoom + double-tap zoom,
  preloading via `ImagePipeline` (memory LRU + disk cache), automatic page/chapter progress
  persistence, safe-area/Dynamic-Island aware chrome.
- **Offline** — `DownloadManager` actor: queue with pending/active/done/error states, retry/cancel,
  per-chapter folders named after the Android convention (`sourceId/manga/chapter`), storage usage
  and cleanup. Downloads persist across launches; iOS background time is used opportunistically.
- **Backups** — import of gzipped Mihon/Tachiyomi/Yomi Protobuf backups via a pure-Swift
  inflate + protobuf decoder; **inspection step** lists restored/missing sources and never deletes
  existing data; every import requires explicit confirmation. Export writes the same schema.
- **Settings/tracking** — reader defaults, appearance (Yomi dark theme tokens), local notifications
  for download completion, tracker framework with honest "requires configuration" status for
  MyAnimeList/AniList (OAuth authorization-code + PKCE flows need registered client credentials;
  nothing is faked).

## 6. Technical limitations (honest)

1. **Android APK extensions cannot run on iOS.** See `IOS_COMPATIBILITY.md` §Extension for the
   full explanation (dynamic code loading is prohibited on iOS; code signing is mandatory).
2. **No Windows-side compilation of the app.** Windows can author and test `YomiKit` logic (with a
   Swift toolchain), but `xcodebuild`/simulator/device deployment require macOS.
3. **Trackers** ship as an integration framework; live MyAnimeList/AniList sync needs registered
   OAuth applications (credentials supplied by the user later; never committed).
4. **Widgets/Glance, Shizuku, APK installers, Firebase** are Android-only and out of scope.
5. **Local source (CBZ)** is scheduled post-v1; the protocol already accommodates it.

## 7. Compliance boundaries

- No circumvention of iOS code signing, platform security, or executable-code restrictions.
- No remote code execution is added anywhere in the iOS app.
- The bundled `SampleSource` produces deterministic, original, procedurally generated artwork —
  no third-party copyrighted content is scraped, bundled, or distributed.
